# Supplementary material

*Companion to `docs/paper_draft.md`. Every artifact referenced here exists in the
repository **at submission time**; nothing in this document depends on work performed
after submission. Numeric authority is `docs/project_results_registry.csv` (278 rows,
each carrying a scope).*

---

## S1. The scope discipline in full

Seven scopes, and what each may claim:

| scope | what it may claim | rows |
|---|---|---:|
| `deployable` | end-to-end performance of a shippable path; no oracle, no human key in the answer path, denominator not oracle-selected | 49 |
| `oracle_free_component_eval` | prediction path is oracle-free, but the **denominator is oracle-selected**; a component result only | 25 |
| `delivered` | the delivered pipeline's own output, scored against a key | 75 |
| `proposal_ceiling` | an oracle-evaluated upper bound on proposals | 26 |
| `identity_oracle` | consumes human-supplied identity; a **bound**, never system performance | 45 |
| `definition-change` | the benchmark definition moved, not the model | 13 |
| `bug-diagnostic` | a correctness fix; never a model before/after | 38 |

Answer production and grading are separate functions: no layer that produces an answer
may read an expected value, and a syntax-tree test fails the build if a deployable
answer function so much as binds a key-shaped name.

## S2. Transfer protocol: the full amendment history

The main paper (§4.3) discloses that the generator was amended twice. The complete
record is `docs/arkitscenes_rgb_transfer_test.md`, which contains:

- the protocol as frozen, at commit `95246f0`, before the capture was downloaded;
- **Amendment 1** (run voided and regenerated): run 1's eight questions returned with
  four marked ambiguous, leaving n = 4 with zero cross-view items, at which size the
  coverage gate degenerates into an anti-abstention gate. Three fixes were applied —
  scope wording, anchor ordering, question count;
- **Amendment 2**: relational slots restricted to unique-referent anchors, after the
  ordering fix was found to promote the *most numerous* anchors;
- the self-imposed limit: "no further structural amendment to this generator on this
  scene", with the stated consequence if run 2 had also failed.

**What protects the result**: the blinded model never ran in run 1 — no response was
ever requested — so nothing scored was selected on an outcome, and both amendments
addressed defects visible in the questions alone. The run-1 key was overwritten at its
tracked path and survives only inside commit `6ee7715`.

**Blinding, stated precisely.** For the transfer run the key was recorded at commit
`45f8ec9` and the response hash-pinned at `e193e6f` eight minutes later, so commit order
does **not** prove the response predates the key. What the record establishes is that
the response was produced in a context that never received the key, and was pinned by
hash before any score was computed. The protection is isolation plus the hash pin, not
version-history ordering.

## S3. The reachability ledger

`docs/paper_reachability_ledger.csv` — one row per question, with a column for every
stage an answer must survive, and the arms' per-item outcomes. Generated by
`tools/paper_statistics.py`, which reads only the tracked evidence pack and runs no
model.

A naming caution carried in the ledger and enforced by a test: the column
`evidence_spans_multiple_views` is **not** the transfer test's *cross-view*. The
transfer items are non-co-visible by construction; this flag only records that an answer
drew on more than one view, which a co-visible question can also do. The two counts must
never be pooled.

## S4. Paired statistics

`eval/results/paper_statistics.json`. Exact two-sided binomial tests on discordant pairs
(not the chi-square approximation — the discordant counts are far too small for it):

| comparison | fixed | regressed | p | scope |
|---|---:|---:|---|---|
| splat → rgb_tight, top-1 `[G01]` | 12 | 1 | 0.00341797 | `oracle_free_component_eval` |
| splat → rgb_tight, top-3 `[G02]` | 14 | 0 | 0.00012207 | `oracle_free_component_eval` |
| delivered graph → human identity `[G06]` | 7 | 0 | 0.015625 | `identity_oracle` |

**Clustering limitation.** The 21 label instances sit within only three scenes and the
test treats them as independent, which they are not: instances in one room share a
capture, a lighting condition and a reconstruction. These are instance-level statements,
not scene-level or dataset-level ones. `[G06]`'s ten items come from two rooms with one
non-blind reviewer, and the p-value inherits every limitation of that key.

## S5. Replica supporting decomposition, per scene

Delivered instance recovery at IoU 0.50: 12/47 `[A05]`, 17/45 `[A25]`, 18/53 `[A48]`.

Proposal ceilings share those denominators but are a **different quantity** and are not
comparable to the delivered rows: pooled per-entity maxima reach 33/53 `[B03]`, 19/47
`[B06]` and 26/45 `[B09]` against baselines 20/53 `[B01]`, 13/47 `[B04]` and 21/45
`[B07]`. The generator alone scores 25/53 `[B02]`, 12/47 `[B05]` and 13/45 `[B08]` —
below the Mask3D baseline on both transfer scenes. `[B09]`'s +5 meets its predeclared
gate with zero margin, and the regime is prospective transfer at fixed settings, not
sealed-holdout: those scenes' keys and frozen baselines pre-existed the protocol.

**The semantics revision spans two scopes.** `[E01]` (5/20) is `proposal_ceiling`,
measured on a variant consuming the dataset's oracle boxes and labels; `[E02]` (16/20) is
`definition-change`. Support-relation citation precision on that scene is 0.94 `[E03]`.
The 0.58 `[E10]` and 0.36 `[E12]` figures reported on two further scenes are
**scene-aggregate micro-precision across all relations** — a different metric on a
different denominator, not the fall of 0.94. The comparable relation-level precisions
exist only in an untracked run report and are recorded as unverifiable.

## S6. Evidence pack and reproducibility

`eval/results/project_census_v1/` — 18 sanitized numeric reports with original paths,
sha256 of both original and sanitized bytes, and producing commits, plus `MANIFEST.json`.
Sanitization policy (bulk keys dropped, oversized lists elided) is applied by
`tools/evidence_pack_add.py`, which never regenerates a report.

Twenty-eight of the 278 registry rows cite an untracked primary source and cannot be
reproduced from the repository alone. A further 52 quantities could not be verified
against any committed artifact and are enumerated in `docs/project_results_census.md`
rather than entered in the registry. None is load-bearing for any claim in §5.

## S7. Claim-to-registry audit

`docs/paper_claim_audit.csv` — 42 rows mapping each paper claim to its `result_id`s,
their scopes, their values, and the caveat that must accompany them. Machine-checked on
every test run by `tests/tools/test_paper_claim_audit.py`, which fails the build if the
paper cites an id absent from the registry, states a quantity no registry row asserts,
calls a component result end-to-end, cites an `identity_oracle` row without marking it a
bound, or headlines the exploratory support result.
