\section{Method: staged evaluation with explicit scope}
\label{sec:method}

Terminology, used consistently throughout: an \emph{arm} is an evaluated system
configuration; a \emph{path} is an arm's route through the evaluator's stage DAG; the
\emph{key} is the human-authored expected-answer record a question is scored against; a
\emph{gate} is a predeclared numeric threshold committed before the corresponding score
exists; \emph{delivered} denotes the pipeline's own output partition, produced without
oracle input; the \emph{bridge} is the oracle-free grounding module binding question
anchors to delivered instances. Bracketed codes such as \rid{F25} index rows of the
results registry that accompanies the submission; they are not citations.

\subsection{The scope discipline}

Every measurement carries one of seven scopes, enforced in code rather than promised in
prose. Four matter for the results below: \texttt{deployable} (end-to-end performance of
a shippable path; no oracle, no human key in the answer path, and the denominator is not
oracle-selected); \texttt{oracle\_free\_component\_eval} (the prediction path is
oracle-free, but the \textbf{denominator is oracle-selected} --- a component result
only); \texttt{delivered} (the pipeline's own output, scored against a key); and
\texttt{identity\_oracle} (consumes human-supplied identity --- a \textbf{bound}, never
system performance). The remaining three --- \texttt{proposal\_ceiling},
\texttt{definition-change} and \texttt{bug-diagnostic} --- are defined in the
supplement, along with the full row counts.

Answer production and grading are separate functions: no component that produces an
answer may read an expected value, and a syntax-tree test fails the build if a deployable
answer function so much as binds a key-shaped name.

\subsection{The arms}

Five arms answer the same questions over the same stored relations, differing only in
where object identity comes from: a geometry ceiling and a stored-edge replay, both
consuming human identity; the delivered graph, using its own learned labels; a grounded
graph, using an oracle-free bridge; and direct multiview RGB, which uses no graph at all.
\Cref{fig:ladder} shows which pipeline stages each arm relies on.

\subsection{The StageReach3D evaluator}
\label{sec:evaluator}

Each arm is evaluated along a declared \emph{path}: an ordered subset of a fixed
universe of eight stages (\cref{tab:paths}). Paths are data, not convention; a stage a
path does not declare is bypassed, and a \texttt{not\_applicable} status is legal only
there. Two stages the vocabulary keeps distinct:
\texttt{serialization\_consistency} --- the serialized edge agrees with recomputation
under the same convention --- is measured on the ARKit slice, while
\texttt{relation\_correctness} --- semantic truth of the relation against independent
ground truth --- is an \emph{audit} stage: non-gating, and \texttt{unknown} on ARKit,
where no independent semantic annotation exists.

The evaluator's invariants are tests, and a violation raises rather than warns:
(i) \texttt{unknown} never counts as pass in survival;
(ii) a deployable-scope trace may not pass-consume any oracle-fed answer-path stage;
(iii) no silent bypass --- any reached status downstream of a fail on a depended-on
stage is an error, and \texttt{not\_applicable} is legal only on declared bypasses;
(iv) no pooled accuracy --- metrics are keyed by (expected outcome, result), positives
are never pooled with true-empties, and no single ``accuracy'' is exposed;
(v) under a non-exhaustive key the evaluator refuses to emit precision, recall or
true-negative metrics;
(vi) definition-change results cannot be pooled with frozen-track results.

\subsection{Predeclaration}

Gates, stopping rules and interpretation limits are written and committed before the
corresponding scores exist. Twice this caught a \emph{structurally unreachable} outcome
before measurement: a predeclared clause that cannot fire is a broken instrument, not a
null result, and only a check in advance reveals it. In the first relation experiment the
routing structure made the accuracy clause unreachable, and it duly came in at exactly
$0.0000$ \rid{F25} with the proceed decision \texttt{false} \rid{F27}.

Blinded responses are generated in an isolated context with \textbf{no access to the key}
and hash-pinned before scoring. The protection is isolation plus the hash pin, not
version-history ordering: for the transfer run the key was recorded before the response
was pinned, so commit order does not prove the response predates the key. The full
chronology and the transfer protocol's amendment history are in the supplement.


\subsection{Experimental setup}
\label{sec:setup}

Every component below was frozen before the results in \cref{sec:component} and
\cref{sec:unreachable} were produced, and no constant was tuned between scenes.

\paragraph{Data.}
Four ARKitScenes validation captures (handheld iPad, 60\,Hz low-resolution wide stream
with per-frame poses and intrinsics) and four Replica scenes. Geometry is the
dataset-supplied mesh; the annotation boxes are used only by the evaluator, never by an
answer path.

\paragraph{Delivered instances.}
A frozen class-agnostic Mask3D bundle, resolved to a dense partition at
$\text{MIN\_SCORE}=0.2$, $\text{min\_vertices}=20$, $\text{dbscan\_eps}=0.95$. The
partition is an input to every arm and is never re-resolved between arms.

\paragraph{Label stage.}
OpenCLIP \texttt{ViT-B-32-quickgelu} with \texttt{openai} weights, $\text{top\_k}=3$,
admission threshold $\text{min\_top1\_score}=0.28$ on raw cosine similarity (uncalibrated),
over a fixed 41-class indoor vocabulary. Three prompt templates are scored per class ---
``a photo of a \{c\}'', ``a photo of a \{c\} in a room'', ``a 3D render of a \{c\}'' ---
and the per-class score is the maximum over templates. The three arms differ only in the
images: \texttt{splat} renders three isolated point splats per instance;
\texttt{rgb\_tight} takes real capture crops at 0.15 box padding with no marking; and the
\texttt{rgb\_context} control takes crops at 0.6 padding with the target dimmed. Crops
come from a fixed multiview source (every 6th posed frame, three views per instance, a
24\,px minimum crop side). Evaluation matches delivered instances one-to-one to
annotation-box vertex sets greedily at vertex $\text{IoU}\ge 0.50$.

\paragraph{Graph relation.}
\texttt{NEAR} holds when the axis-aligned bounding boxes of two instances are within
$1.0$\,m surface-to-surface (strict less-than). The same convention defines the human
key. Comparative items are ordinal and use no threshold. Edge absence is a measurement,
not a missing value: the extractor emits no top-$k$ truncation.

\paragraph{Grounding bridge.}
The oracle-free bridge encodes anchor phrases and the same real capture crops with the
same pinned OpenCLIP weights. A slot score is the maximum over the anchor's name and its
declared synonyms; the entity score is the mean over that entity's available view slots;
ranking is by aggregate descending, ties by identifier ascending. An entity is admitted
only if it also wins at least two independent view slots. \textbf{No confidence threshold
is applied or swept anywhere in the bridge.}

\paragraph{Direct multiview RGB.}
Claude Opus 5 (Anthropic), single pass, one response per packet, no retries and no
self-consistency sampling. Frames are selected answer-free: 18 equal temporal bins across
the capture, and within each bin the frame with the highest information score (contrast
and edge density, penalising clipping). The selector cannot see any question. The
response schema is fixed --- per item an identifier, an \texttt{outcome} of
\texttt{answer} or \texttt{unknown}, the answer, a confidence in $[0,1]$, and evidence
frame identifiers drawn only from the 18 supplied --- and the response must pin the hash
of the packet it answered. Declining is a first-class outcome, distinct from answering
wrongly.
