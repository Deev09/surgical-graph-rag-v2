\section{The reachability ledger}
\label{ssec:ledger}

The question-level bookkeeping behind ``held but unreachable'' ships with
the submission as a packaged artifact,
\texttt{paper\_reachability\_ledger.csv}: one row per question, with a
column for every stage an answer must survive, and the arms' per-item
outcomes. It is generated by the packaged statistics tool, which reads only
the tracked evidence pack and runs no model --- every cell is a re-reading
of outcomes that were already scored and committed, so the transition where
questions are lost can be read off rather than argued.

Figure~\ref{fig:supp-ladder} gives the one-glance overview of the arms the
main paper's path table declares: which stages each arm relies on, which
consume human-supplied identity, and what each reaches.

\begin{figure*}[t]

  \includegraphics[width=\textwidth]{figures/fig1_evaluation_ladder}

  ledger's pipeline vocabulary; the evaluator's declared stages are the

  \label{fig:supp-ladder}

A naming caution carried in the ledger and enforced by a test: the column
\texttt{evidence\_spans\_multiple\_views} is \emph{not} the transfer test's
\emph{cross-view}. The transfer items are non-co-visible by construction;
this flag only records that an answer drew on more than one view, which a
co-visible question can also do. The two counts must never be pooled.
