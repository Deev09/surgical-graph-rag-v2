\section{Trace schema and path declarations}
\label{ssec:schema}

Every evaluated item emits one trace conforming to the frozen schema below
(\texttt{stagereach\_trace}, schema version~1). \texttt{source} is a
provenance string naming the artifact and field the status was derived from.
Every emitted artifact carries its schema name and version and is written
with sorted keys, with byte-compare support for staleness checking.

\begin{center}
\footnotesize
\begin{verbatim}
{
 "schema": "stagereach_trace",
 "schema_version": 1,
 "question_id": "...",
 "scene_id": "...",
 "arm": "...",
 "path_id": "...",
 "scope": "...",
 "expected_outcome": "answer|empty|defer",
 "stages": [
   {"stage": "...",
    "status": "...",
    "source": "..."}
 ],
 "final_outcome": {
   "result": "correct|wrong|abstain|excluded",
   "positive_expected": true
 },
 "raw_category": "verbatim source vocabulary label"
}
\end{verbatim}
\end{center}

\paragraph{A concrete committed trace.} The main paper's Fig.~3 question
(the basket--desk \texttt{NEAR} item) on the grounded arm, as committed
(schema header, scene id, provenance strings and raw category elided):
{\scriptsize
\begin{verbatim}
{"question_id": "q25_bin_basket_near_desk",
 "arm": "grounded_delivered_graph",
 "path_id": "graph_deployable_grounded",
 "scope": "deployable", "expected_outcome": "answer",
 "stages": [
  {"stage":"key_eligibility",       "status":"pass"},
  {"stage":"object_delivery",       "status":"pass"},
  {"stage":"relation_applicability","status":"pass"},
  {"stage":"relation_correctness",  "status":"unknown"},
  {"stage":"serialization_consistency","status":"pass"},
  {"stage":"referent_grounding",    "status":"fail"},
  {"stage":"answer_generation","status":"not_reached"}],
 "final_outcome": {"result": "abstain"}}
\end{verbatim}}

A stage status is one of \texttt{pass}, \texttt{fail}, \texttt{unknown},
\texttt{not\_applicable}, \texttt{abstain}, \texttt{not\_reached}.
\texttt{unknown} is never counted as \texttt{pass}, never attributed as a
failure, and never zeroes downstream survival; \texttt{not\_applicable} is
legal only on stages the trace's path declares bypassed; and
\texttt{not\_reached} is required downstream of a \texttt{fail} on a
depended-on stage. Causal survival is computed over declared gating
dependencies only; non-gating audit stages remain visible but do not reduce
downstream reachability, and attribution reports the first \texttt{fail} on
a gating stage.

\paragraph{Per-arm path declarations.} There is no shared mixed ladder:
each arm declares its own ordered stage subset as data
(\cref{tab:paths}). Stages carry two attributes, \texttt{answer\_path} and
\texttt{oracle\_fed}: \texttt{key\_eligibility} is
\texttt{answer\_path=False, oracle\_fed=True} on every path, and
\texttt{identity\_injection} is \texttt{answer\_path=True,
oracle\_fed=True}; a \texttt{deployable}-scope trace may not
pass-consume any oracle-fed answer-path stage, and the evaluator raises if
one tries. Gating dependencies are declared per stage per path:
\texttt{serialization\_consistency} does \emph{not} depend on
\texttt{relation\_correctness}, and \texttt{relation\_correctness} is a
non-gating audit stage on the ARKit paths; on ARKit \texttt{NEAR} it is
\texttt{unknown} (no independent semantic annotation exists) while
serialization consistency is measured.
